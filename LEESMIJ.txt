PURE20 STACKS IN CUSTOMER ACCOUNT

Supabase is already configured. A protected table 'pure20_saved_stacks' has been created.

Replace only these 6 files in the root of the GitHub repository:
- account.html
- account.css
- account.js
- stack-builder.html
- stack-builder.css
- stack-builder.js

WHAT CHANGES

STACK BUILDER
- keeps local autosave
- adds 'Save to account'
- adds 'My stacks'
- if not signed in, the customer is sent to /account and returned to the Stack Builder after login
- when an account stack is opened, /stack-builder?stack=<id> loads it from Supabase
- saving again updates the same cloud stack
- Print / PDF still works as before

CUSTOMER ACCOUNT
- new 'Stacks' tab
- lists saved stacks
- shows title, last update, number of compounds and duration when available
- Open reopens the exact stack in the Stack Builder
- Delete removes it from the customer's account
- each customer can only access their own saved stacks through Supabase RLS

SECURITY / FUNCTION
- saved stacks are tied to Supabase Auth user_id
- RLS allows authenticated users to select/insert/update/delete their own stacks only
- PURE20 admins can also access rows through the existing admin check
- the stack data is organizational data only; the builder does not generate recommended compounds, doses, routes or schedules
